# 依据论文生成方法框架图

[English guide](method-framework.en.md)

目标：把已经理解并核查的方法转换成可编辑、可追溯的结构图。保持论文阅读的证据标准，不把概念上“可能存在”的模块画成论文实际实现。

## 1. 先抽取关系，再布局

读取原文 Methods、架构图及图注、输入输出定义、相关公式与训练描述。内部先列出下表，再生成图；最终可以将其合并为图下的来源表：

| 节点/关系 | 输入与输出 | 阶段 | 证据位置 | 状态 |
| --- | --- | --- | --- | --- |
| 具体模块、数据、损失或箭头 | 对象或信号的含义 | 训练/推理/评估 | 页码、章节、图或公式 | 原文明确/本次推断/未报告 |

只标注核实的维度、参数、频率与公式。论文没有学习模型时使用实验、计算或论证流程，不强行加入神经网络或损失函数。

优先区分：

- 训练数据与部署输入，尤其真值、未来信息、特权状态和标签。
- 训练目标与模型输出，损失计算与参数更新。
- 冻结模块与可训练模块，离线训练与在线更新。
- 数据流与控制反馈；反馈箭头注明信号，避免看起来像瞬时的代数环。
- 本文方法、比较基线和消融变体；不要把不同实验条件拼成同一个系统。

## 2. 图的内容与尺度

默认画一张清晰概览；模块较多时拆为“训练流程”和“推理/部署流程”，或再加局部细节图。通常每张图约5–12个主要节点，复杂论文可以调整。图中强调输入、核心变换、输出与关键连接，而不是堆叠所有超参数。

输出顺序为：图的目的与范围 → 图 → 图注与图例 → 节点/关键箭头来源表 → 未报告、简化或待核查事项。

对于控制系统，检查名义控制量与残差控制量是否真正相加、状态反馈是否闭合、历史动作的时间索引是否明确。对估计器与控制器分阶段训练的系统，不画成未经原文支持的端到端联合训练。

## 3. 默认格式：Mermaid

使用 `flowchart LR` 或 `flowchart TB`，节点ID采用简短的 `snake_case`，文字标签加双引号。适当使用 `subgraph` 区分阶段；包含 `accTitle` 和单行 `accDescr`，方便无障碍阅读。避免主题初始化指令、交互链接、脚本及过长标签。

原文支持的流程使用实线；本次推断若确有必要，用虚线并显式写“推断”。参数更新或反馈使用带文字的箭头，在图例说明其含义；不要仅靠颜色区分证据状态。使用 `classDef` 做少量配色，保持黑白阅读可辨。

完整精读后应画实际方法，而不是把“输入→模型→输出”的通用占位图当作完成品。查看 [风感知RL框架图示例](../examples/wind-aware-rl-framework.md)，了解训练与部署分离及来源标注方式。

## 4. 图片及文件导出

默认在聊天或报告中嵌入 Mermaid 源码；渲染取决于宿主。用户请求保存时，提供包含图注和来源表的 Markdown，以及需要时的独立 `.mmd` 源文件。若不能渲染，应交付源码并说明，而不是声称已经看到渲染图。

用户需要可下载图片时，优先SVG；PNG用于兼容性或明确的分辨率要求。有可用的本地Mermaid渲染器时可直接渲染。也可按同一已核查关系重建Graphviz `.dot` 并导出，例如环境已安装Graphviz时：

```bash
dot -Tsvg method-framework.dot -o method-framework.svg
dot -Tpng -Gdpi=300 method-framework.dot -o method-framework.png
```

Mermaid和Graphviz是不同语法；不能把 `.mmd` 直接交给 `dot`。若保留两种源文件，逐项核对节点、箭头、标签和图例一致。Graphviz是可选导出依赖，不是安装或调用本Skill的必需条件。渲染器不可用时保留源码，遵循环境的安装权限规则。

实际导出后检查文件非空、可打开、文字清晰、无裁切和遮挡、箭头方向正确。SVG在需要时用临时PNG预览。不得仅凭文件存在就宣称版面正确；无法视觉检查时明确说明。

## 5. 交付检查

- 图是否符合实际论文，而非只沿用摘要或原图外观？
- 真值是否仅在论文实际允许的阶段出现？
- 反馈、残差相加、冻结关系、训练目标是否正确？
- 每个影响理解的节点和连接是否可定位到原文，推断是否标明？
- 图注是否说明它是“依据论文重建”，并解释关键简化？
- 用户只要求画图时，是否聚焦必要的方法核查，而未强制整篇第三遍评审？

该功能是本项目为AI阅读增加的操作能力，不宣称来自原指南的具体绘图要求。
